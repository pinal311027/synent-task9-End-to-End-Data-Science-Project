1. PROJECT OVERVIEW
================================================================================

This project is a COMPLETE END-TO-END DATA SCIENCE PROJECT that predicts 
whether a patient has heart disease based on clinical features.

The 5 major phases are:
  1. Data Collection — Merged 3 Kaggle datasets into one
  2. Data Cleaning — Fixed bad values, encoded categories, augmented data
  3. EDA — Created 11 professional visualizations
  4. Model Building — Trained 5 ML models, tuned top 3
  5. Deployment — Built interactive Streamlit web app

Final Result: Random Forest model with 96.98% accuracy and 97.28% F1-Score

2. PROBLEM STATEMENT & MOTIVATION
================================================================================

PROBLEM:
  Cardiovascular disease is the #1 cause of death globally, responsible for 
  approximately 17.9 million deaths per year (WHO). We need a tool that can 
  predict heart disease risk from readily available clinical measurements.

MOTIVATION:
  - Early detection saves lives
  - Machine learning can assist doctors in identifying at-risk patients
  - This project demonstrates a full data science lifecycle

OBJECTIVE:
  Build an ML-based system that takes 11 clinical features as input and 
  predicts whether a patient has heart disease (binary classification: 0 or 1).

USE CASES:
  - Early Intervention — Identify high-risk patients before symptoms worsen
  - Decision Support — Data-driven insights for clinical judgment
  - Screening Tool — Rapid risk assessment during routine checkups

NOTE: This is for educational/research purposes only, NOT a replacement for 
      professional medical diagnosis.

STEP A: DATA COLLECTION  (src/data_collection.py)
================================================================================

WHAT IT DOES:
  - Downloads 3 separate heart disease datasets from Kaggle using kagglehub
  - Maps each dataset to a COMMON SCHEMA (unified column names)
  - Merges all 3 datasets into one combined DataFrame
  - Removes duplicates and NaN rows
  - Saves the merged dataset to data/heart.csv

DETAILED PROCESS:

  1. DATASET 1 — fedesoriano (918 rows):
     - Already has correct column names with string categoricals
     - Encoded: Sex (M→1, F→0), ChestPainType (TA→0, ATA→1, NAP→2, ASY→3),
       RestingECG (Normal→0, ST→1, LVH→2), ExerciseAngina (N→0, Y→1),
       ST_Slope (Up→0, Flat→1, Down→2)

  2. DATASET 2 — johnsmith88 (1,025 rows):
     - Has old-style column names (age, sex, cp, trestbps, etc.)
     - Renamed columns to match common schema
     - Already has numeric encoding

  3. DATASET 3 — redwankarimsony (920 rows):
     - Has string categoricals and multi-class target (num: 0-4)
     - Encoded string values to numeric
     - Converted target from multi-class to binary (0 vs 1+)

  4. MERGING:
     - Concatenated all 3 DataFrames
     - Converted all columns to numeric
     - Dropped rows with NaN values
     - Removed exact duplicates
     - Result: 1,220 unique records

  5. SAVED TO: data/heart.csv

COMMON SCHEMA (12 columns = 11 features + 1 target):
  Age, Sex, ChestPainType, RestingBP, Cholesterol, FastingBS,
  RestingECG, MaxHR, ExerciseAngina, Oldpeak, ST_Slope, HeartDisease

KEY FUNCTION: download_dataset(force=False)
  - Returns: merged DataFrame
  - Uses _load_fedesoriano(), _load_johnsmith88(), _load_redwankarimsony()

================================================================================
STEP B: DATA CLEANING & PREPROCESSING  (src/data_cleaning.py)
================================================================================

WHAT IT DOES:
  - Fixes data quality issues
  - Validates value ranges
  - Augments data using Gaussian noise injection
  - Saves cleaned dataset to data/heart_cleaned.csv

THE 6-STEP CLEANING PIPELINE:

  STEP 1: Handle Missing Values
    - Checked for NaN values
    - If found, filled numerical columns with MEDIAN values
    - Result: 0 missing values

  STEP 2: Remove Duplicates
    - Used df.drop_duplicates()
    - Removed exact duplicate rows

  STEP 3: Fix Zero Cholesterol
    - Found 172 rows with Cholesterol = 0 (biologically impossible!)
    - Replaced zeros with MEDIAN of non-zero cholesterol values
    - WHY? A person cannot have 0 cholesterol — it's a data entry error

  STEP 4: Validate Ranges
    - Fixed RestingBP = 0 → replaced with median
    - Fixed negative Oldpeak → set to 0
    - Clipped values to valid ranges:
        Age:         [18, 120]
        RestingBP:   [60, 250]
        Cholesterol: [50, 700]
        MaxHR:       [50, 220]

  STEP 5: Data Augmentation (GAUSSIAN NOISE INJECTION)
    - WHY? 1,220 rows is small for ML. We need more data for robust training.
    - HOW? For each synthetic sample:
        a) Randomly pick a real row as "seed"
        b) Add small Gaussian noise (5% of std) to numerical features
        c) Occasionally flip categorical values (3% chance) except target
    - Generated per-class to maintain class balance
    - Result: 1,220 → 3,478 rows
    
    CODE LOGIC:
      noise = np.random.normal(0, std * 0.05)  # 5% of standard deviation
      seed_row[col] = seed_row[col] + noise
    
    - Cleaned synthetic data: rounded integers, clipped to valid ranges

  STEP 6: Final Shuffle
    - Shuffled entire dataset using random_state=42 for reproducibility
    - Saved to data/heart_cleaned.csv

KEY FUNCTION: clean_data(df=None, verbose=True)
  - Returns: cleaned & augmented DataFrame (3,478 rows × 12 columns)

STEP D: MODEL BUILDING & EVALUATION  (src/model_building.py)
================================================================================

WHAT IT DOES:
  - Prepares data (splits, scales)
  - Trains 5 ML models
  - Cross-validates all models
  - Tunes hyperparameters for top 3
  - Generates model comparison visualizations
  - Saves best model + scaler + metadata

DETAILED PROCESS:

  ── D.1: DATA PREPARATION ──

  - Split: 80% training, 20% testing (test_size=0.2)
  - Used stratify=y to maintain class balance in both sets
  - Applied StandardScaler (fit on training, transform both)
  - StandardScaler formula: z = (x - mean) / std
  - WHY SCALE? Algorithms like SVM, KNN, Logistic Regression are distance-based
    and sensitive to feature scales. StandardScaler ensures all features have
    mean=0 and std=1.
  - Training set: 2,782 samples
  - Test set: 696 samples

  ── D.2: MODELS TRAINED (5 Models) ──

  1. LOGISTIC REGRESSION
     - Type: Linear model for binary classification
     - Parameters: max_iter=2000, solver='lbfgs', C=1.0
     - How it works: Fits a sigmoid function to predict probability
     - Pros: Simple, interpretable, fast
     - Cons: Assumes linear decision boundary

  2. RANDOM FOREST ⭐ (BEST MODEL)
     - Type: Ensemble of Decision Trees
     - Parameters: n_estimators=200, max_depth=10
     - How it works: Builds many decision trees and takes majority vote
     - Pros: Handles non-linearity, feature importance, robust
     - Cons: Can overfit, less interpretable

  3. GRADIENT BOOSTING
     - Type: Sequential ensemble (boosting)
     - Parameters: n_estimators=200, learning_rate=0.1, max_depth=5
     - How it works: Builds trees sequentially, each correcting previous errors
     - Pros: Very accurate, handles complex patterns
     - Cons: Slower training, sensitive to hyperparameters

  4. SUPPORT VECTOR MACHINE (SVM)
     - Type: Finds optimal hyperplane
     - Parameters: kernel='rbf', C=1.0, gamma='scale'
     - How it works: Maps data to higher dimensions to find separating boundary
     - Pros: Effective in high-dimensional spaces
     - Cons: Slow on large datasets, needs scaling

  5. K-NEAREST NEIGHBORS (KNN)
     - Type: Instance-based / lazy learner
     - Parameters: n_neighbors=7, weights='distance'
     - How it works: Classifies based on k closest training examples
     - Pros: Simple, no training phase
     - Cons: Slow at prediction time, needs scaling

  ── D.3: CROSS-VALIDATION ──

  - Used 5-Fold Stratified Cross-Validation
  - StratifiedKFold preserves class distribution in each fold
  - Scoring metric: accuracy
  - WHY? Prevents overfitting by testing on multiple unseen folds

  ── D.4: HYPERPARAMETER TUNING ──

  - Tuned TOP 3 models using GridSearchCV
  - GridSearchCV tries all combinations of parameters and picks the best
  - Scoring metric: F1-score
  - Used 5-fold CV internally

  TUNING PARAMETERS:

  Random Forest:
    - n_estimators: [100, 200, 300]
    - max_depth: [5, 8, 10, 15, None]
    - min_samples_split: [2, 5, 10]
    - min_samples_leaf: [1, 2, 4]
    BEST: max_depth=None, min_samples_leaf=1, min_samples_split=2, n_estimators=300

  Gradient Boosting:
    - n_estimators: [100, 200, 300]
    - learning_rate: [0.01, 0.05, 0.1, 0.2]
    - max_depth: [3, 5, 7]
    - subsample: [0.8, 1.0]
    BEST: learning_rate=0.2, max_depth=7, n_estimators=300, subsample=1.0

  KNN:
    - n_neighbors: [3, 5, 7, 9, 11, 15]
    - weights: ['uniform', 'distance']
    - metric: ['euclidean', 'manhattan']
    BEST: metric=manhattan, n_neighbors=11, weights=distance

  ── D.5: MODEL VALIDATION ──

  After selecting the best model, validated with EXTREME TEST CASES:
  
  Test Case 1 — Healthy 25-year-old Female:
    Input: Age=25, Sex=0, ChestPainType=0, RestingBP=110, Cholesterol=180,
           FastingBS=0, RestingECG=0, MaxHR=190, ExerciseAngina=0, Oldpeak=0, ST_Slope=0
    Expected: No Disease → Model correctly predicts No Disease (~96% confidence)

  Test Case 2 — Risky 70-year-old Male:
    Input: Age=70, Sex=1, ChestPainType=3, RestingBP=180, Cholesterol=350,
           FastingBS=1, RestingECG=2, MaxHR=90, ExerciseAngina=1, Oldpeak=4.0, ST_Slope=1
    Expected: Heart Disease → Model correctly predicts Disease (~87-93% confidence)

  ── D.6: MODEL SAVING ──

  Saved using joblib:
    - best_model.pkl    → Serialized Random Forest model (~16 MB)
    - scaler.pkl        → StandardScaler for input transformation
    - model_metadata.json → Model name, metrics, feature names

  ── D.7: VISUALIZATION GENERATION ──

  5 model evaluation plots saved to artifacts/model_metrics/:
    1. model_comparison.png   → Grouped bar chart of all metrics
    2. confusion_matrices.png → Confusion matrices for all 5 models
    3. roc_curves.png         → ROC curves with AUC scores
    4. feature_importance.png → Random Forest feature importance
    5. cv_comparison.png      → 5-fold CV box plot comparison

  - F1-Score:    97.28%

WHY RANDOM FOREST WAS CHOSEN:
  - Highest F1-Score (97.28%) — best balance of precision and recall
  - Near-perfect recall (97.91%) — very few false negatives
  - In medical diagnosis, HIGH RECALL is crucial because:
    Missing a sick patient (false negative) is worse than a false alarm
  - Robust to overfitting with ensemble approach
  - Provides feature importance scores

EVALUATION METRICS EXPLAINED:
  - Accuracy: % of correct predictions overall
  - Precision: Of predicted positives, how many are actually positive
  - Recall: Of actual positives, how many did we catch
  - F1-Score: Harmonic mean of precision and recall
  - ROC-AUC: Area under ROC curve (1.0 = perfect, 0.5 = random)
  - Cross-Validation: Average accuracy across 5 different train/test splits

8. KEY EDA FINDINGS
================================================================================

  1. CLASS BALANCE: ~55% positive (disease) vs ~45% negative — fairly balanced

  2. AGE FACTOR: Patients aged 55+ show significantly higher heart disease 
     prevalence

  3. GENDER DISPARITY: Males have significantly higher heart disease rates 
     than females

  4. CHEST PAIN: Asymptomatic patients (ASY) have the highest disease rate (~80%)

  6. ST DEPRESSION: Oldpeak values are significantly higher in disease patients

9. INTERVIEW Q&A — COMMON QUESTIONS & ANSWERS
================================================================================

Q1: What is this project about?
A: This is an end-to-end data science project that predicts heart disease risk 
   from 11 clinical features using machine learning. It covers the full lifecycle: 
   data collection, cleaning, EDA, model building, and deployment as a web app.

Q2: What dataset did you use?
A: I merged 3 Kaggle datasets (fedesoriano, johnsmith88, redwankarimsony) 
   containing heart disease records from UCI Machine Learning Repository. After 
   merging and deduplication, I got 1,220 unique records, which I augmented to 
   3,478 using Gaussian noise injection.

Q3: Why did you merge 3 datasets?
A: To increase the dataset size for more robust model training. A single dataset 
   had only ~920 rows. Merging gave us 1,220 unique records after deduplication, 
   providing more diverse patient profiles.

Q4: What is Gaussian noise augmentation and why did you use it?
A: It's a technique where we create synthetic samples by adding small random 
   noise (5% of standard deviation) to numerical features of existing records. 
   I used it because 1,220 rows is relatively small for ML. The augmentation 
   expanded the dataset to 3,478 rows while preserving the underlying 
   distribution. Categorical features are occasionally flipped with 3% 
   probability (except the target variable).

Q5: How did you handle zero cholesterol values?
A: 172 records had cholesterol = 0, which is biologically impossible. I replaced 
   them with the median cholesterol value of non-zero records. This is called 
   median imputation and is preferred over mean imputation because it's robust 
   to outliers.

Q6: Why did you choose Random Forest as the best model?
A: Because it achieved the highest F1-Score (97.28%) with excellent recall 
   (97.91%). In medical diagnosis, recall is critical because missing a sick 
   patient (false negative) is more dangerous than a false alarm (false positive).

Q7: What is F1-Score and why is it important here?
A: F1-Score is the harmonic mean of precision and recall. It gives equal weight 
   to both. In healthcare, we need both high precision (avoid false alarms) and 
   high recall (don't miss sick patients). F1 balances these two needs.

Q8: Explain cross-validation.
A: 5-Fold Stratified Cross-Validation divides data into 5 equal folds, trains 
   on 4 folds and tests on 1, rotating the test fold 5 times. "Stratified" 
   means each fold preserves the class distribution. It gives a more reliable 
   estimate of model performance than a single train/test split.

Q9: What is hyperparameter tuning?
A: It's the process of finding the best configuration for a model. I used 
   GridSearchCV which exhaustively tries all combinations of specified parameter 
   values and picks the one with the highest F1-score through cross-validation.

Q10: What is StandardScaler and why did you use it?
A: StandardScaler standardizes features by removing the mean and scaling to 
   unit variance (z = (x - mean) / std). It's essential for algorithms like 
   SVM, KNN, and Logistic Regression that are distance-based and sensitive to 
   feature scales. Without it, features with larger ranges would dominate.

Q11: Why did you fit the scaler on training data only?
A: To prevent data leakage. If we fit on the entire dataset, the scaler would 
   "know" information about the test set (like its mean and std), giving an 
   unrealistically optimistic performance estimate.

Q12: What is the ROC curve?
A: ROC (Receiver Operating Characteristic) curve plots True Positive Rate vs 
   False Positive Rate at various threshold values. AUC (Area Under Curve) 
   summarizes performance: 1.0 = perfect, 0.5 = random. Our best model has 
   99.24% AUC, indicating near-perfect separation.

Q13: What is a confusion matrix?
A: A table showing predictions vs actual values:
   - True Positive (TP): Predicted disease, actually has disease
   - True Negative (TN): Predicted no disease, actually healthy
   - False Positive (FP): Predicted disease, actually healthy (Type I error)
   - False Negative (FN): Predicted no disease, actually has disease (Type II error)

Q14: How does Random Forest work?
A: It's an ensemble method that creates multiple decision trees (300 in our case) 
   using random subsets of data and features. Each tree votes on the prediction, 
   and the majority vote wins. This reduces overfitting and improves accuracy.

Q15: What deployment framework did you use?
A: Streamlit — a Python framework for building data science web apps. It allows 
   creating interactive UIs with pure Python code. The app has 4 pages: Home, 
   EDA Dashboard, Prediction, and Model Performance.

Q16: How do you make predictions in the deployed app?
A: The user enters 11 clinical features through sliders and dropdowns. The input 
   is arranged in the correct feature order, standardized using the saved scaler, 
   then passed to the saved Random Forest model. The model returns the prediction 
   (0 or 1) and probability scores, displayed with a confidence gauge chart.

Q17: What are the most important features for prediction?
A: Based on feature importance from Random Forest and correlation analysis:
   1. ST_Slope (strongest predictor)
   2. ExerciseAngina
   3. Oldpeak (ST depression)
   4. ChestPainType
   5. MaxHR

Q18: What is data leakage and how did you prevent it?
A: Data leakage occurs when information from the test set influences training. 
   I prevented it by:
   - Fitting StandardScaler on training data only
   - Splitting data before any preprocessing that uses statistics
   - Using stratified splitting to maintain class distribution

Q19: What encoding did you use for categorical variables?
A: Label encoding (ordinal encoding). For example:
   - Sex: M→1, F→0
   - ChestPainType: TA→0, ATA→1, NAP→2, ASY→3
   - RestingECG: Normal→0, ST→1, LVH→2
   - ExerciseAngina: N→0, Y→1
   - ST_Slope: Up→0, Flat→1, Down→2

Q20: What are some limitations of this project?
A: - Dataset may not represent all populations
   - Gaussian augmentation can introduce slight distribution shifts
   - No deep learning models were tested
   - No SHAP/LIME for model interpretability
   - Not validated on external clinical data
   - Should NOT replace actual medical diagnosis

Q21: What would you improve in the future?
A: - Add SHAP values for model explainability
   - Test deep learning models (PyTorch/TensorFlow)
   - Add feature engineering (interaction features, polynomial terms)
   - Implement ensemble methods (stacking/blending)
   - Add FastAPI REST endpoint
   - Dockerize the application
   - Deploy to cloud (AWS/GCP/Streamlit Cloud)
   - Add CI/CD pipeline

Q22: Why is recall more important than precision in medical diagnosis?
A: Because a false negative (missing a sick patient) can lead to death — the 
   patient goes home thinking they're healthy. A false positive (false alarm) 
   just leads to additional tests. Our model has 97.91% recall, meaning it 
   catches 97.91% of all heart disease patients.

Q23: How does the Streamlit caching work?
A: @st.cache_resource caches the model and scaler so they're loaded only once 
   (not reloaded on every page interaction). @st.cache_data caches the dataset. 
   This significantly improves app performance.

Q24: What is the difference between fit_transform() and transform()?
A: fit_transform() calculates statistics (mean, std) AND transforms the data. 
   Used on training data. transform() only applies the already-calculated 
   statistics. Used on test data to prevent data leakage.

Q25: What libraries are used for visualization?
A: matplotlib (static plots), seaborn (statistical visualizations like heatmaps),
   and plotly (interactive gauge chart in the web app).
